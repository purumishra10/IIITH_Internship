====================================================
WEEK 1 - TASK 1: Extracting Images from a YouTube Video
====================================================

WHAT IS THE BIG GOAL?
----------------------
Think of a video like a flip book. When you flip the pages fast,
it looks like things are moving. But each page is actually just
one still picture. In this task, we:
1. Downloaded a YouTube video to our computer
2. Used a tool called ffmpeg to "rip out" individual images from that flip book


THE TOOLS WE USED
------------------
Tool 1 - yt-dlp:
  A free program that acts like a "Save" button for YouTube.
  It downloads any YouTube video straight to your computer
  from the command line.

Tool 2 - ffmpeg:
  A powerful free tool that can do almost anything with video
  and audio files. Think of it as a Swiss Army knife for videos.
  In this task we used it to slice the video into individual image frames.


STEP BY STEP - WHAT EXACTLY HAPPENED
--------------------------------------

STEP 1: Opened Command Prompt and navigated to the project folder
  Command used:
    cd /d D:\Puru_VNR\Projects\IIITH\Internship

  What it does:
    Opens our working folder on the D: drive.
    The /d flag is needed to switch drives (from C: to D:) at the same time.


STEP 2: Downloaded the YouTube video using yt-dlp
  Command used:
    yt-dlp -f mp4 "https://youtu.be/zhEWqfP6V_w" -o video.mp4

  What each part means:
    yt-dlp                            = the download tool
    -f mp4                            = download in MP4 format
    "https://youtu.be/zhEWqfP6V_w"   = the YouTube link of the video
    -o video.mp4                      = save the file as video.mp4

  Result:
    A file called video.mp4 appeared in our Internship folder.


STEP 3: Created a folder to store the extracted images
  Command used:
    mkdir frames

  What it does:
    Creates an empty folder called "frames" to keep all our
    extracted images organised in one place.


STEP 4: Extracted multiple images from the video using ffmpeg
  Command used:
    ffmpeg -i video.mp4 -vf fps=1/5 -q:v 2 frames\frame%03d.jpg

  What each part means:
    ffmpeg                  = the video tool we are using
    -i video.mp4            = input file is video.mp4
    -vf fps=1/5             = take 1 photograph every 5 seconds
    -q:v 2                  = save at very high image quality (scale: 1=best, 31=worst)
    frames\frame%03d.jpg    = save images inside the frames folder,
                              named frame001.jpg, frame002.jpg, frame003.jpg and so on

  Result:
    A series of .jpg image files appeared inside the frames folder,
    each one being a snapshot taken from a different moment in the video.


STEP 5: Verified the images were created
  Opened File Explorer and navigated to:
    D:\Puru_VNR\Projects\IIITH\Internship\frames\

  Could see image files: frame001.jpg, frame002.jpg, frame003.jpg ...
  Double clicking any one opened it as a normal photograph.


THE FULL FLOW - WHAT HAPPENED BEHIND THE SCENES
-------------------------------------------------

  YouTube Video (online)
          |
          |  yt-dlp downloads it
          |
     video.mp4  (saved on your computer)
          |
          |  ffmpeg reads the video
          |
          |  Extracts 1 image every 5 seconds
          |
  frame001.jpg, frame002.jpg, frame003.jpg ...
  (all saved inside the frames\ folder)


WHY DOES THIS MATTER?
----------------------
This task teaches something very fundamental about how computers see video:

- A video is not a continuous flowing stream. It is actually thousands
  of still images shown very fast (usually 24 to 30 per second).

- ffmpeg lets you go in and grab any of those individual images.

- This is the foundation of many real-world applications like CCTV analysis,
  sports tracking, self-driving cars, and medical imaging. All of these work
  by processing individual frames from a video one at a time.

In the next tasks (Task 2, Task 3, and the Advanced Task), we built directly
on top of this - extracting 1800 frames, rebuilding them into a video, adding
music, and running AI object detection on each frame. It all started with this
one simple idea: a video is just a lot of photos played fast.
